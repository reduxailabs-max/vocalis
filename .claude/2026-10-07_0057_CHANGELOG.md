## Rulings and deviations carried over from the Tasks 1–9 ledger (progress.md)

- Task 1: lazy `librosa` import inside `apply_speed()`; minor deferred items
  (unused `logger`, unused `sample_rate` param, no ndim check).
- Task 2: negative-cache TTL (15s, injectable clock) + `mark_failed(None)`
  clears a cached None, because the service may start before the sound
  system is ready. Minor deferred: stale preference-switch cache edge case,
  a tiny positive remaining probe budget still opens a stream, concurrency
  test strictness not absolute.
- Task 3: factory-raises gap fixed with a hook + one retry via a fresh
  provider answer. Minor polish items deferred: first error lost on a
  failed retry, a few missing tests, docstring wording.
- Task 4: `config.py` now imports `vocalis.audio.pace` (and therefore numpy)
  at import time (~0.28s cold) since `config.py` loads very early; accepted
  as a reasonable DRY trade-off. Minor: nan test case lacks a comment.
- Task 5: pause/resume restructuring (`_play_chunk_until_done` helper) —
  resuming now replays the already-paced chunk instead of resynthesizing;
  user-visible effect: a speed change made while paused applies only from
  the next chunk. Minor polish items deferred (speed_provider freshness
  test, helper docstrings, caplog message matching).
- **Task 6 (spike) — VERDICT NOT EFFECTIVE.** Qwen3-TTS 0.6B CustomVoice's
  `instruct` parameter produces no measurable, direction-consistent,
  above-threshold change in duration or pitch. Means vs. the no-instruct
  baseline: natural −2.11% duration/+7.12% pitch, slow −0.42% duration
  (wrong direction)/+2.70% pitch, fast −3.80% duration/+4.76% pitch — all
  inside the no-instruct condition's own repeat-to-repeat noise (6.3%
  duration spread, 16.3% pitch spread across 3 "identical" runs).
  Temperature *does* control variance as expected (0.9 gives ~3x the
  duration spread of 0.6), confirming the harness was sound. Full report:
  `.superpowers/sdd/2026-10-06-vocalis-stage1-sound-and-voice/reports/task-6-report.md`.
- Task 7 — **SKIPPED** per the plan's conditional on the Task 6 verdict. No
  `voice_style` config field, no STYLES dict, no style control in Settings.
- Task 8: no issues on review; one false-alarm deviation note (a duplicate
  combo-box line the brief asked to remove was already absent).
- Task 9: "notify once per switch" was ruled, after a fix round, to mean
  "notify once per DIFFERENT failed device" (reset when a different device
  fails than the last one notified about). Fix round addressed: a silent
  device being reported as a Test-sound success, and a named device with a
  fallback showing the picked device succeeded when the tone actually
  played elsewhere. Minor deferred: ~8 older `main()` tests still call the
  real `sd.query_devices()` (metadata only, no stream/no sound — see
  `docs/developer-docs.md`); `_device_name()` runs outside its try at the
  success path; unused preference lambda at the named-device path; private
  `_output_devices()` access (noqa SLF001, acceptable).
