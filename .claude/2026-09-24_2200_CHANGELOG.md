# Changelog — 2026-09-24 (Phase 2 fast-follow fix)

## Vocalis Phase 2: fast-follow fix — NUMLOCK device hygiene

Fast-follow fix for the third finding from Phase 2's final review
(deferred at merge time, now addressed):

**Fixed:**
- `vocalis.hotkeys.numlock.list_numlock_capable_devices()` no longer
  watches Vocalis's own `ydotoold virtual device` — the app was watching
  the very virtual device it uses to type transcribed text back out.
  The NUMLOCK-capability check and the exclusion check are now both in a
  small, independently unit-tested `_is_watchable()` helper.
- `vocalis.features.dictation.DictationFeature` now ignores a duplicate
  NUMLOCK press while already recording, and a duplicate release while
  not recording, instead of raising/reporting confusing errors. This
  guards against a real key-remapping tool (`keyd`, present on the
  target machine) occasionally re-emitting one physical press as two
  press/release event pairs.

**Not changed:** `ModelManager`, CLI/config wiring, docs, `old/`. Both
fixes are narrowly scoped to the two files (and their tests) above.

**Rollback:** revert this commit; both fixes are additive guards with no
behavioral change to the existing single-press/release happy path (all
pre-existing tests pass unchanged).
