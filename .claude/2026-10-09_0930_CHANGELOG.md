## Documentation drift fixed (Task 5)

Each doc was compared line by line against the source it describes.

1. **`docs/architecture.md`** (most significant): said the Unix socket carries real feature commands to a separate daemon. Wrong. Every feature is wired in-process in `cli.py`'s `main()`, and the socket's only real job is the single-instance guard. Also added a short section on the three installer robustness fixes (unit-template path fallback, `PATH` export after installing `uv`, idempotent venv creation).
2. **`docs/user-docs.md`**: the uninstall paragraph did not say `--purge` also removes Piper's binary and voice, and did not mention `uninstall.sh --help`. Both added.
3. **`docs/workflow.md`**: the `uninstall.sh` flow diagram was missing the `-h`/`--help` and unknown-option branches, and said `--purge` reads two model directories when it actually reads four. Corrected.
4. **`docs/file-purpose.md`**: stopped at Stage 3. Missing the root `README.md` and the new whole-system test file. Added a Stage 4 section. Also fixed the `uninstall.sh` description (Piper).
5. **`docs/folder-structure.md`**: same gaps as file-purpose.md (README and test file missing, `uninstall.sh` Piper note). Added both.
6. **`docs/algorithms.md`**: had no section for speaking-pace time-stretch (`audio/pace.py`) or the single-instance socket probe (`daemon.py`), though the project rules require every core algorithm to be documented. Added both sections.
7. **`docs/developer-docs.md`**: no drift found (test and type-check commands matched exactly). Only addition: a section explaining the whole-system test file.
