# Changelog — 2026-09-14

## Vocalis Phase 2, Task 4: Text Output (type via ydotool, clipboard fallback)

Added the piece of Vocalis that actually puts the transcribed words on the
screen. After the microphone (Task 2) records what the user said and the
speech-to-text engine (Task 1) turns it into words, this new piece types
those words wherever the user's cursor is — like someone else typing on
your keyboard for you. If typing doesn't work for some reason (the typing
helper program isn't running, or anything else goes wrong), it copies the
text to the clipboard instead, so the user can just paste it in with
Ctrl+V and never loses their words.

**Added:**
- `vocalis.output` — a new small package for delivering text to the user.
- `vocalis.output.typer.TextOutput` — the class that delivers text.
  - `deliver(text)` first tries to "type" the text at the cursor using a
    helper program called `ydotool`. If that fails for any reason at all
    (the helper program is missing, it times out, or it reports an error),
    it automatically copies the text to the clipboard using another helper
    program called `xclip` instead.
  - Empty text is safely ignored (nothing happens, no error).
  - `deliver()` is guaranteed to never crash the program — even if both
    typing AND the clipboard copy fail, it just reports what happened
    instead of raising an error that could take down the whole app.
  - `vocalis.output.typer.OutputResult` — a small report object saying how
    the text was delivered (`"typed"` or `"clipboard"`) and what the text
    was, so the feature that uses this later (Task 6) and, eventually, the
    on-screen notification (Task 5) can tell the user what happened.
  - The actual calls to `ydotool` and `xclip` go through one small
    injectable "command runner" seam, so every automated test can pretend
    to run those programs without ever touching the real keyboard or
    clipboard on this machine.
- `tests/test_typer.py` — 6 automated tests using a fake pretend command
  runner: empty text does nothing, successful typing never touches the
  clipboard, a failed typing attempt falls back to the clipboard, a
  missing `ydotool` program falls back to the clipboard, a typing timeout
  falls back to the clipboard, and even if the clipboard copy ALSO fails,
  nothing crashes.
