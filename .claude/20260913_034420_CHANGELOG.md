# Changelog — 2026-09-13

## Vocalis Phase 2, Task 2: Microphone Capture

Added the microphone-recording building block that the upcoming Dictation
feature (Task 6) will use to capture what the user says while a hotkey is
held down.

**Added:**
- `vocalis.audio` package (`src/vocalis/audio/__init__.py`).
- `vocalis.audio.capture.MicRecorder` — records mono float32 audio from the
  microphone into memory while `start()`/`stop()` bracket the recording.
  - `start()` opens the audio stream; raises `RecordingAlreadyActiveError`
    if called twice without a `stop()` in between.
  - `stop()` closes the stream and returns everything captured so far as a
    1-D `float32` NumPy array (empty array if nothing was captured).
  - `is_recording` property reports whether the stream is currently open.
  - Built-in safety cutoff (`max_duration_seconds`, default 60s): if
    `stop()` is never called (e.g. a stuck key), the audio stream is force-
    closed automatically. Audio already captured before the cutoff is not
    lost — a later `stop()` call still returns it.
  - The real microphone stream (`sounddevice.InputStream`) is only used by
    default; tests inject a fake stream factory so no test ever touches
    real audio hardware.
  - Shape matches the `Recorder` interface planned for Task 7 (CLI wiring):
    `start() -> None`, `stop() -> npt.NDArray[np.float32]`,
    `is_recording: bool`.
- `tests/test_capture.py` — 6 unit tests covering: start opens a stream,
  stop with no audio returns an empty array, stop concatenates captured
  chunks in order, double-start raises, stream is stopped+closed on
  stop(), and the safety cutoff stops the stream early while still
  preserving captured audio for the next `stop()` call.

**Changed:**
- `pyproject.toml`:
  - Added `sounddevice>=0.4.6,<1` (microphone I/O) — required by this task.
  - Added `numpy>=1.26,<3` — `capture.py` imports NumPy directly and this
    working branch was created before Task 1 (which separately adds NumPy
    for the STT engine) was merged in; declaring it here keeps this
    branch's tests and strict `mypy` runnable on its own. When Task 1 and
    Task 2 are merged together, the `numpy` line will simply already match
    — no conflict expected.
  - Added a `[[tool.mypy.overrides]]` entry for `sounddevice` (it ships no
    type stubs / `py.typed` marker) so strict `mypy` stays clean without
    weakening strictness anywhere else.

**Verification:**
- TDD followed: wrote `tests/test_capture.py` first, ran it and observed
  the expected `ModuleNotFoundError: No module named 'vocalis.audio.capture'`
  failure, then implemented `capture.py` to make it pass.
- Focused tests: `tests/test_capture.py` — 6/6 passed.
- Full suite: 49/49 tests passed; coverage 94.15% (gate is ≥85%).
- Strict `mypy`: `Success: no issues found in 17 source files`.
- Manual smoke test against the real microphone device on this machine:
  the stream opened and closed without error, but recorded 0 samples in
  the sandboxed dev environment used for this task (no audio actually
  reaches the callback here — likely no live capture backend attached to
  this container/session). Code path, locking, and error handling were
  otherwise verified entirely through the fake-stream unit tests. This
  should be re-verified with a real microphone on the target desktop
  before this is relied on in the actual Vocalis daemon.

**Not yet implemented (future phases):** nothing consumes `MicRecorder`
yet — Task 6 (DictationFeature) will call `start()`/`stop()`, and Task 7
(CLI wiring) will construct the real instance.

**Rollback:** this task is additive only (one new package + one dependency
+ one mypy override). Reverting is `git revert` back to before this
changelog's commit.
