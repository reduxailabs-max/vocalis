# Phase 6 — UI (tray icon, floating widget, Settings window) change log

## What was added
- A **tray icon** (grey idle / red listening / blue reading, tooltip, menu: status, Pause/Resume, Stop, Open Document Reader, Settings…, Quit).
- A **floating widget** shown only while reading (source, status, progress, Pause/Resume + Stop; Quick Reader is Stop-only; never takes keyboard focus). OCR shows it instead of the Document Reader window unless the widget is switched off.
- A **Settings window**: notifications switch and widget switch (apply immediately), voice (nine voices, applies on the next reading), four shortcuts (apply after a restart; the window says so). Duplicate/invalid shortcuts are refused ("Not saved: …").
- **Shortcuts are really read** now (before, the config values were ignored). A bad hand-edited shortcut logs a clear error and the defaults are used.
- `LiveSettings` (shared live settings) and `StatusHub` (status board) tie it together.
- Saved config file is now **private to the user (mode 0600)** and written atomically.
- Closing the Settings/Document Reader window no longer quits Vocalis; Quit in the tray menu = Ctrl+C.

## Decisions and rulings
- QMenu cannot be parented to the TrayIcon; kept as an attribute and deleted in `TrayIcon.close()` (accepted).
- Quick Reader reports from state under a `_report_lock` (replaced the plan's `_deactivate` rule).
- `on_started` is announced after the coordinator hand-over (the plan's order was wrong).
- `TrayIcon.close()` added (idempotent), called before `app.quit()` and on shutdown.
- `QApplication` and `StatusHub` are created before the builders; keepalive timer stopped and deleted on exit (fixed a full-suite segfault).
- PySide6 stub gaps: one `cast` and one `type: ignore[arg-type]`.
- Polish round: notifier guard, `save_config` cleanup on any failure, ASCII-only shortcut keys, stale-generation Quick Reader claim fix, test tightening.

## Deferred minors
- `LiveSettings.update()` has no writer lock (the Settings window is the only writer).
- No fsync before the config rename.
- `QuickReader._report_lock` is not re-entrant (hub hooks do not re-enter).
- Hub emits after unlocking: begin/end from different threads at the same instant could be delivered out of order (features call them consistently; documented).
- With the widget on, an OCR reading still sends status/progress/finished to the popup, which never receives the OCR text.
- Switching the widget on mid-reading shows it at the next reading.
- `TrayIcon.available` stays True after `hide()`.

## Known issues
- ALSA `default` output is silent on the author's machine (use the `pulse` device for hands-on runs).
- Ctrl+C while a screen-capture box is open is not specially handled.

## Final review
Fixed: I1 (a document reading now reports its end before sending the "Done"/error notification), M1 (the reading claim is released under the feature lock in Quick Reader and Document Reader), M3 (restart note compares parsed shortcuts), M4 (Settings window clears its message when reopened).

- Pre-existing `time.sleep(0.2)` negative checks in `tests/test_numlock.py` (lines ~103/118).
