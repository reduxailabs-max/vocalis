# Changelog — 2026-09-14

## Vocalis Phase 2, Task 6: DictationFeature (the piece that ties everything together)

This is the big one — it connects all the separate pieces built in Tasks
1-5 into the actual "dictation" feature: hold down NUMLOCK, speak, let go,
and your words appear wherever your cursor is. Nothing built before this
task actually talked to anything else; this is the glue.

**Added:**
- `vocalis.features` — a new package for "feature" code (code that wires
  hotkeys and other triggers to the underlying engines and outputs).
- `vocalis.features.dictation.DictationFeature` — the class that does the
  wiring:
  - `on_press()` — call this when NUMLOCK goes down. It shows a
    "Listening..." pop-up and starts the microphone recording. If the
    microphone can't start (e.g. it's busy), it shows a "Could not start
    recording" pop-up instead of crashing.
  - `on_release()` — call this when NUMLOCK comes back up. It:
    1. Stops the microphone and grabs what was recorded. If stopping the
       microphone itself fails, it shows "Recording failed" and stops
       there.
    2. If nothing was recorded (silence, or too short), it shows "No
       audio captured" and stops — it does not even try to load the
       speech-to-text model for no reason.
    3. Otherwise it shows "Transcribing..." and borrows the speech-to-text
       engine from the shared `ModelManager` (the GPU traffic-cop built in
       Phase 0/1) to turn the audio into text. The engine is always handed
       back to `ModelManager` afterwards — even if the transcription
       itself blows up — so the GPU traffic-cop's bookkeeping never gets
       stuck thinking the model is still "checked out."
    4. If transcription fails for any reason, it shows "Transcription
       failed" and stops.
    5. If the model transcribed nothing but blank/silence text, it shows
       "(no speech detected)" and does not bother trying to type nothing.
    6. Otherwise it shows the live transcript as a pop-up, then hands the
       text to `TextOutput` to actually type it out. If typing failed and
       it had to fall back to the clipboard, it says so
       ("Typing failed — copied to clipboard instead"); otherwise it just
       says "Done".
  - At every single step above, nothing this class does is allowed to
    crash the whole program — a broken microphone, a broken speech
    engine, or a broken typing helper all just show a pop-up message and
    let the user try again, instead of taking the whole dictation feature
    down.
- `tests/test_dictation.py` — 8 automated tests, using stand-in "fake"
  versions of the microphone, speech engine, text output, and pop-ups
  (each of those is already tested for real in its own file), but using
  the **real** `ModelManager` — the actual GPU traffic-cop code, not a
  fake — to prove the "borrow the engine, always give it back" wiring
  genuinely works: pressing starts recording and shows "Listening...";
  releasing transcribes, delivers the text, and shows "Done"; silence
  skips transcription; a blank transcript skips typing; a transcription
  crash is caught and reported without taking down the app (and the
  engine still gets handed back to `ModelManager` afterwards); a
  clipboard fallback is reported as such; and both a broken microphone
  start and a broken microphone stop are caught and reported instead of
  crashing.

**A bug found (and fixed) while following TDD, not just followed blindly:**
While turning the plan's example test code into a real, running test file,
two of the eight tests genuinely failed even with the plan's own suggested
code — not because anything was missing, but because of a real
misunderstanding baked into the plan. The plan's tests build a plain,
default `ModelManager()` and then check, immediately after `on_release()`
finishes, that the borrowed engine has been fully unloaded
(`current_engine_id is None`). But `ModelManager` (built in an earlier
task, already tested and correct) was deliberately designed to keep a
model "warm" for a little while after it's returned, in case dictation is
used again right away — it does not unload the model the instant it's
returned; it starts a background timer and only unloads it after the
GPU has sat idle for a while (30 seconds, by default). So checking "is it
unloaded yet?" one line after returning it will always say "no, not yet"
— that's the correct, tested behavior of `ModelManager`, not a bug in it.
The fix was to give those two tests a real, but very short (0.05 second)
idle timer instead of the 30-second default, and a short pause (0.2
seconds) before checking — the exact same pattern the project's own
`tests/test_model_manager_integration.py` already uses to prove the real
timer really works. This keeps the tests using the real `ModelManager`
(no pretend/fake stand-in for it) while actually being able to pass, and
proves the borrow/return wiring end-to-end instead of asserting something
that could never be true. `DictationFeature`'s own code was not changed
for this — only the test file's setup for those two tests.
