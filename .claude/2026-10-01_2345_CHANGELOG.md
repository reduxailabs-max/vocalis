# Changelog — 2026-10-01 23:45 EAT

## Phase 4: Document Reader (Ctrl+Alt+D) — implemented

Built on branch `worktree-vocalis-phase4-document-reader` (13 feature/fix
commits from `47aadf9` to `4de3199`, then a final fix wave
`84bf598`, `60f08ac`, `df36ba3`). Every task was written by a fresh
subagent, then checked by an independent reviewer. Full suite at the end:
208 tests passing, 93.15% coverage.

### What was added

- **Text pipeline** (`src/vocalis/text/`): a markdown-to-speakable-text
  normalizer, a sentence-bounded chunker, and extractors for
  txt / md / pdf / docx / html (corrupt, encrypted, image-only and
  oversized files give a clear message instead of crashing).
- **Hotkey listener** (`hotkeys/ctrl_alt_key.py`): one listener that works
  for any Ctrl+Alt+<key>; Ctrl+Alt+R is now a thin wrapper around it.
- **ReadingCoordinator** (`features/reading_coordinator.py`): Quick Reader
  and Document Reader can never speak at the same time; starting one stops
  the other.
- **DocumentReaderFeature** (`features/doc_reader.py`): extract, normalize,
  chunk, speak each chunk with Qwen3-TTS (permanent fallback to Piper for
  the rest of a document on the first failure), with Pause / Resume / Stop
  and progress reporting.
- **Popup** (`ui/doc_popup.py`): PySide6 window with Open file, paste box,
  Read, Pause/Resume, Stop, status and progress labels.
- **cli.py**: `build_doc_reader()`; `main()` now runs a Qt event loop
  instead of a bare sleep loop; Ctrl+C quits the loop through a SIGINT
  handler so listeners, the daemon and the model manager shut down cleanly.
- **Config**: `doc_tts` default changed from `fish_speech` to `qwen3_tts`
  (in `config.py` and `config/default_config.toml`).
- **Docs**: architecture, file purposes, folder structure, workflow,
  algorithms, user docs and developer docs updated for all of the above;
  stale "blocks until Ctrl+C" statements corrected.

### Real bugs the review process caught (all fixed, each with a regression test)

- Task 3: text inside Word tables was silently dropped; four helper
  functions had no docstrings.
- Task 1: bold/italic stripping corrupted `text_input`, `__init__.py`
  and "2 * 3 * 4".
- Task 5: the plan's own test had an inverted expected value.
- Task 6: a race between a fast Resume and the worker thread; Pause pressed
  while a chunk was still being generated was ignored (audio kept playing);
  a Stop could report "finished" twice.
- Task 7: seven popup methods had no docstrings.
- Task 8: with the plan's design, Ctrl+C would not stop the Qt loop, so
  clean shutdown (and model release) would be skipped.
- Final review: the Ctrl+Alt+D hotkey thread touched the popup widget
  directly (not allowed by Qt; now goes through a Qt signal); a Quick
  Reader stopped mid-prepare could be left stuck "active" after Document
  Reader preempted it (preemption is now idempotent).

### Known follow-ups (deliberately not done in this phase)

- Switching between Quick Reader and Document Reader reloads the Qwen3
  model each time (they use different ModelManager engine ids for the same
  model); one shared id would avoid it.
- Stopping via the popup buttons or a preempting Quick Reader waits on the
  desktop notification (latency only).
- Pause shown after a reading already ended still flips the button label.
- A microsecond window where one more chunk can start after Stop.
- Nested tables inside Word tables are not read.
- `doc_reader.py` coverage sits near the 85% floor (a few error paths
  untested).
- 14 mypy errors that existed before this phase remain in four test files
  (`test_clipboard.py`, `test_playback.py`, `test_piper_tts.py`,
  `test_quick_reader.py`); this phase added none.
- Real-hardware check still to do by hand: Ctrl+Alt+D, then Ctrl+Alt+R in
  the middle of a document, then Ctrl+C.
